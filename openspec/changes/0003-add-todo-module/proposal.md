# Proposal: Todo 待办清单模块

## Why

项目当前只有 hello 页面与健康检查地基，缺少一个完整业务模块来验证「规范 → 实现 → 验收」的闭环。Todo 待办清单是经典 CRUD 场景：功能边界清晰、异常路径丰富，适合作为第一个业务模块。

## 模块边界

### 包含（In Scope）

- Todo 创建：标题（10~100 字符）必填，描述、标签、优先级、截止时间可选
- Todo 列表查询：返回当前用户全部待办（按创建时间降序）
- Todo 更新：标题 / 描述 / 完成状态 / 标签 / 优先级 / 截止时间
- Todo 删除：物理删除
- 标签：最多 5 个，每个 1~20 字符，重复自动去重
- 优先级：枚举 `LOW` / `MEDIUM` / `HIGH`，默认 `MEDIUM`
- 截止时间：可选，ISO-8601 格式
- 单用户私有隔离：请求头 `X-User-Id` 识别用户，数据互不可见
- 创建幂等：请求头 `Idempotency-Key` 防重复点击产生重复数据
- 参数校验与统一异常响应（空值、超长、非法枚举、越权、重复点击、更新不存在 id）

### 不包含（Out of Scope）

- 多人协作：共享、指派、邀请、评论
- 分组、到期提醒通知（截止时间字段本身支持，仅不做提醒推送）
- 分页、搜索、按标签 / 优先级筛选（v1 全量返回当前用户数据）
- 软删除 / 回收站 / 历史版本
- 附件、富文本描述
- 登录注册与会话认证（v1 以请求头传递用户标识，认证体系另行提案）
- 前端 Todo 页面（本变更只定义并实现后端 API 契约，页面另行提案）
- 数据持久化（v1 内存存储，服务重启即清空；数据库接入另行提案）

## Impact

- 新增 capability：`todo-module`
- 后端新增 `com.wanderchina.todo` 包：Controller / Service / 内存仓库 / 幂等支持 / 校验
- 复用 `backend-scaffold` 既有的统一响应 `ApiResponse<T>` 与全局异常处理，不修改其规格
