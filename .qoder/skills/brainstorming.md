# brainstorming（头脑风暴）

## 何时触发

- 用户提出"做某件事"但需求模糊、动机不明
- 在 `propose` / 写代码之前

## 执行方式

1. 一次只问一个问题，先弄清 What（要什么）与 Why（为什么），再谈 How（怎么做）
2. 不要急着给方案；用提问引导用户自己把需求说清楚
3. 用户描述告一段落后，用自己的话回放理解，请用户纠正
4. 小改动在对话内达成共识即可；大需求产出书面设计文档供后续 planning 使用

## 输出

- 澄清后的需求描述与验收标准
- （大需求）设计文档

## 注意

- 此阶段不写任何代码、不创建任务清单
- 发现需求矛盾立即指出并要求澄清
